WebUI — how it works
====================

Source
------
llama.cpp WebUI is built as three separate files served from disk via the --path flag:

  index.html   ~7 KB   loader/shell; fetches bundle.js and bundle.css
  bundle.js    ~6 MB   compiled Svelte app (chat, MCP servers, settings, …)
  bundle.css   ~500 KB styles

The files are committed to the llama.cpp source tree at:
  tools/server/public/

They are identical to what the release binary would embed; the release CI does not rebuild
the frontend. This means any tagged release commit is a safe source for the files.

Updating
--------
Run update-llama-cpp.sh (in the repo root). It:
  1. Downloads the llama.cpp release binary + dylibs for the host architecture.
  2. Downloads index.html, bundle.js, bundle.css at the same tag from GitHub.
  3. Applies the patches described below.
  4. Installs everything into AIChat.app/Contents/Support/Llama.cpp/ and
     AIChat.app/Contents/Resources/WebUI/.
  5. Writes WebUI/version with the build tag (e.g. "b8797") — used for cache-busting.

Reference originals
-------------------
WebUI-{VERSION}.zip (e.g. WebUI-b8797.zip) contains the unpatched originals
(index.html, bundle.js, bundle.css) for diffing against future releases to check
whether the patch patterns still apply.

update-llama-cpp.sh creates this zip automatically after downloading the files,
before applying any patches. Each update removes the previous zip and replaces
it with one named for the new version.

Patches
-------
Two sed command files are applied by the update script:

webui-bundle-css.sed  — custom color scheme + welcome-screen flex rule
  Adjusts --background values so the WebUI background is not pure white/black:
    light mode: oklch(100% 0 0)  -> oklch(98% 0.01 240)  (warm blue-tinted off-white)
    dark mode:  oklch(16%  0 0)  -> oklch(27%  0   0)    (lighter dark background)
  Note: parentheses in the pattern must be escaped (\( \)) because the script
  uses sed -E (extended regex mode).
  Also appends an .aichat-flex{display:flex!important;flex-direction:column;
  align-items:center} rule after .block\! so the welcome screen can adopt flex
  column layout when JS substitution 3 swaps "block!" → "aichat-flex".

webui-bundle-js.sed  — brand the app (4 substitutions, applied in order):
  1. s|Hello there</h1>|AIChat</h1>|
     Renames the welcome-screen heading from the llama.cpp default to AIChat.
  2. s|("System message",)([A-Za-z]{1,3})="llama-ui"|\1\2="AIChat"|
     Renames the UI display name (sidebar label, window title) from "llama-ui"
     to "AIChat".  The Svelte/Vite minifier assigns a short generated variable
     name to this string (e.g. Nx, cX) that changes between builds.  Anchoring
     on the adjacent stable literal "System message", makes the pattern robust.
     Note: a different variable holds the same "llama-ui" value as a SvelteKit
     cache key — the anchor ensures only the display-name variable is rewritten.
  3. s|"pointer-events-auto block!"|"pointer-events-auto aichat-flex"|
     Replaces the Tailwind "block!" class (display:block!important applied when
     the chat is empty) with our custom "aichat-flex" class.  The companion CSS
     rule (see webui-bundle-css.sed) defines aichat-flex as flex column with
     items-center, so CSS order: can reorder children visually.
     Background: prior to b9370 the welcome-screen container had a static
     class="mb-8 px-4 text-center" we could amend with an inline style.  From
     b9370 onward the classes are applied dynamically via Svelte's kr([…]),
     and only an !important rule can override the always-applied "hidden"
     class — hence the swap + custom CSS approach.
  4. s|md:text-3xl">AIChat</h1> <p class="text-muted-foreground md:text-lg">|…|
     Inserts the AIChat.png logo and assigns CSS order: values so it renders
     above the heading.  See "Logo injection" below for the exact constraints.

Logo injection — Svelte 5 DOM traversal constraint
---------------------------------------------------
The welcome screen is a Svelte 5 component.  The compiled JS stores its template as
an HTML string and uses from_html() to create it:

  root_5$i = from_html('<div class="mb-8 px-4 text-center">
                          <h1 ...>Hello there</h1>
                          [space " " → becomes a DOM text-node]
                          <p class="text-muted-foreground ..."> </p>
                        </div>')

Svelte 5 compiles the component's dynamic bindings against the ORIGINAL template
structure using hardcoded sibling offsets:

  var div_3 = root_5$i()               // root <div>
  var p2    = sibling(child(div_3), 2) // child(div_3) → nextSibling → nextSibling
  var text2 = child(p2)                // text-node inside <p>
  template_effect(() => set_text(text2, "Type a message…"))

sibling(node, n) calls node.nextSibling n times — it counts ALL nodes including
whitespace text-nodes.  With the original template the path is:

  child(div_3)       = <h1>           (offset 0)
  sibling(<h1>, 1)   = text " "       (the space between </h1> and <p>)
  sibling(<h1>, 2)   = <p>            (p2 — correct)

Inserting <img> as the FIRST child shifts child(div_3) from <h1> to <img>, making
sibling(…, 2) land on a text-node.  child(text-node) → null → JS crash → blank screen.

Required DOM structure
~~~~~~~~~~~~~~~~~~~~~~
The three direct children of the container div must be, in DOM order:

  [0] <h1>   ← child(div_3)  (Svelte's anchor; must remain first)
  [1] <img>  ← sibling 1     (no text-node before it)
  [2] <p>    ← sibling 2 = p2 (must be exactly 2 steps from <h1>)

Rule: NO whitespace characters between </h1> and <img>, and between <img/> and <p>
in the from_html() string.  Any space or newline creates an extra text-node that
shifts p2 to offset 3, causing a null-dereference and blank screen.

Substitution 3 adds flex layout to the container so CSS order: values control the
visual order independently of DOM order:

  <div … style="display:flex;flex-direction:column;align-items:center">
    <h1 … style="order:2">AIChat</h1>          ← DOM child 0, visual position 2
    <img … style="order:1"/>                    ← DOM child 1, visual position 1 (logo first)
    <p  … style="order:3">                      ← DOM child 2, visual position 3

Verification
~~~~~~~~~~~~
After patching, update-llama-cpp.sh calls verify_welcome_dom() which greps for:
  'AIChat</h1><img src="./AIChat.png"'   — no text-node after </h1>
  'height:128px;order:1"/><p '           — no text-node after <img/>
If either is missing the build is flagged as broken before any files are installed.

Pattern uniqueness (checked in b9370)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Sub 2 match  '"System message",'  followed by  '="llama-ui"'      — 1 occurrence
Sub 3 match  '"pointer-events-auto block!"'                       — 1 occurrence
Sub 4 match  "md:text-3xl\">AIChat</h1> <p class=\"text-muted…"   — 1 occurrence
CSS rule    ".block\\!{display:block!important}"                  — 1 occurrence
Recheck after each llama.cpp upgrade by extracting bundle.js/bundle.css
from WebUI-{VERSION}.zip and grepping for all four strings.

Cache-busting
-------------
WKWebView (used by the OMC engine) aggressively caches HTTP responses from localhost.
Without intervention it serves old cached bundle.js/bundle.css even after the files
on disk have been replaced.

Two-level cache-busting is used:

1. index.html — the update script rewrites the bundle references to include ?v=VERSION:
     ./bundle.css  ->  ./bundle.css?v=b8797
     ./bundle.js   ->  ./bundle.js?v=b8797   (link preload and dynamic import)
   When the version changes, the URLs change and WKWebView fetches fresh copies.

2. index.html itself — aichat.init.sh reads WebUI/version and appends ?v=VERSION
   to the localhost URL it opens in the dialog:
     http://localhost:8088/?v=b8797
   WKWebView has never seen this URL, so it fetches index.html fresh from llama-server,
   which in turn references the versioned bundle URLs from step 1.

After each update both levels flip automatically; no manual cache clearing is needed.
